# K210 视觉模块

草莓成熟度检测（红熟 / 绿未熟）在 K210 上的部署代码与训练产物。

```
K210 (ov2640)  ──UART1 115200──>  STM32F407
   YOLOv2 推理        24B 定长帧 @ ≤100Hz
```

## 1. 模型

**YOLOv2 · 输入 224×224×3 · 输出 7×7×35 · 双类别 `['ripe', 'unripe']`**
参数量 1,859,891（约 1.86 MB kmodel），由 MaixHub 在线训练 + nncase 转换。

**关键结论**：草莓在 224×224 输入下呈**竖长条形**，anchor 的长宽比必须匹配。

## 2. 24 字节定长视觉帧协议

`main.py` 中 `Comm.build_frame()` 实现。固定 24 字节，5 个目标槽位，XOR 校验。

| 偏移 | 长度 | 含义 |
|-----:|-----:|------|
| 0 | 1 | 帧头 `0xAA` |
| 1 | 1 | 有效目标数（0~5） |
| 2 | 20 | 5 个目标槽 × 4 字节 |
| 22 | 1 | 校验：`byte[1] XOR byte[2..21]` |
| 23 | 1 | 帧尾 `0x55` |

每个目标槽 4 字节：

| 槽内偏移 | 含义 | 编码 |
|---------|------|------|
| +0 | 类别 | `0`=成熟(ripe), `1`=未熟(unripe) |
| +1 | 中心 X | `x * 255 / 320`（1 字节压到 320 宽） |
| +2 | 中心 Y | 直接取 `min(y, 240)` |
| +3 | 框面积 | `area * 255 / (320*240)` |

**设计要点**

- **定长帧**：STM32 端可用 UART DMA + IDLE 中断整帧接收，零 CPU 轮询开销，也便于丢帧检测。
- **按 X 排序**：目标写入前按中心 X 升序排列（`target_list.sort(key=lambda t: t['x'])`），
  STM32 侧无需重排即可按从左到右的固定顺序逐个处理。
- **降采样发送**：`send_detect_result()` 限制最小间隔 10 ms（≤100 Hz），
  避免 UART 成为瓶颈，也匹配下位机控制周期。

## 3. 推理参数与稳定化处理

`main.py` 主循环中的几处工程处理：

| 处理 | 取值 | 目的 |
|------|------|------|
| `kpu.init_yolo2` threshold | `0.3` | 放宽召回，把过滤交给下一级 |
| 置信度过滤 | `obj.value() > 0.4` | 滤掉低置信误检 |
| 丢帧保持 | `no_detect_count <= 5` | 短暂遮挡/漏检时沿用上一帧目标，避免目标在协议里"闪烁" |
| 传感器预热 | 开机丢弃 20 帧 | 摄像头自动曝光稳定前的画面不可用 |
| 窗口裁剪 | `sensor.set_windowing((224,224))` | 直接输出模型输入尺寸，省去缩放 |

> **关于阈值**：`0.3`（YOLO 输出）与 `0.4`（应用层过滤）都是按实车表现手调的，
> 调低会引入背景误检、调高会在逆光/遮挡时丢目标。
> 当前版本用的是**全局单一阈值**，两类共用——绿果与背景对比度低、得分整体偏低，
> 统一阈值对它偏严，这是后续可以继续改进的点（按类别分别设阈值）。
